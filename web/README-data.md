# Homepage and feed data contract — HS-015, HS-017, HS-021, HS-056

This directory (`web/data/`, Hugo's `data/` directory) is the production data
path between the Go engine and the Hugo rendering layer.

## Path contract: production vs. fixtures

Issue #247 / PUB-01: generated Hugo data is **no longer tracked in Git**. The
production `web/data/` files are generated by `export run` into the workspace
(and, for the deployed manifest, stored durably in the shared database —
Turso in production). Only the deterministic `web/fixtures/*` demo sample and
the hand-authored `web/content/stories/_index.md` are tracked.

| Path | Tracking | Contents |
|------|----------|----------|
| `web/data/heartbeat.json` | **gitignored / untracked** | Real refresh-run heartbeat (written by `cmd/ingest`/`cmd/export` to the workspace) |
| `web/data/homepage.json` | **gitignored / untracked** | Homepage snapshot written by `cmd/export` to the workspace |
| `web/data/feeds.json` | **gitignored / untracked** | Feed-health snapshot written by `cmd/ingest` to the workspace |
| `web/data/deployed.json` | **gitignored / untracked** | Deployed-manifest stamp, re-projected to the workspace by `publish manifest get` (canonical state lives in Turso) |
| `web/fixtures/homepage.json`, `web/fixtures/feeds.json`, `web/fixtures/content/stories/*.md` | **tracked** | Deterministic 2024 **sample** data, test-only |
| `web/fixtures/dev/` | gitignored | Local development output when you point ingest/export at it |
| `web/content/stories/_index.md` | **tracked** | Hand-authored section index |
| `web/content/stories/*.md` (story pages) | **gitignored / untracked** | Generated story pages written by `stories publish` to the workspace |

After HS-056 the demo sample data no longer lives in the production path. The
live site starts from the *missing-file* state; the first successful `export`
run writes real data to the workspace (and the publish gate compares it
against the deployed manifest stored in Turso, not a committed file). The
demo sample only ever reaches a Hugo build via the test-only fixture overlay
in `scripts/site-test.sh` — never via a production build.

The engine's output locations are configurable (env > config file > default):
`HSC_HEARTBEAT_FILE`, `HSC_FEEDS_FILE`, `HSC_DATA_DIR`, `HSC_DATA_FILE`
(see `.env.example`). Production sets none of these, so the defaults
(`web/data/*`) apply.

## `homepage.json`

The renderable projection of the domain `StoryGroup` (internal/domain/clustering.go)
scored by HS-012 (`internal/domain/scoring.go`). It powers the homepage display.

### Schema (v1)

```json
{
  "version": "1",
  "generatedAt": "2026-11-11T17:00:00Z",
  "stories": [
    {
      "id": "top-free-agents-2024",
      "title": "Top 10 free agent signings of the offseason",
      "summary": "Short, original summary (not full article text).",
      "firstPublishedAt": "2024-07-25T15:30:00Z",
      "lastPublishedAt": "2024-08-01T10:00:00Z",
      "score": 81.5,
      "evidenceLevel": "confirmed",
      "publishers": [
        { "id": "nfl-com", "name": "NFL.com", "url": "https://www.nfl.com/news/..." },
        { "id": "espn-nfl", "name": "ESPN",    "url": "https://www.espn.com/nfl/..." }
      ]
    }
  ],
  "latest": [
    {
      "source_id": "nfl-com",
      "source_name": "NFL.com",
      "title": "Latest story headline",
      "url": "https://www.nfl.com/news/latest",
      "published_at": "2026-11-11T17:00:00Z"
    }
  ],
  "teams": [
    {
      "slug": "49ers",
      "name": "San Francisco 49ers",
      "short_name": "49ers",
      "abbreviation": "SF"
    }
  ]
}
```

#### Top-level fields

- `version` (required, string): export format version (currently `"1"`).
- `generatedAt` (required, string, RFC3339): snapshot timestamp used for the "Data as of" metadata. Never implies real-time.

#### Story fields (within `stories` array)

- `id` (required, string): unique identifier (same as the content page slug under `/stories/`).
- `title` (required, string): headline, not the full article.
- `summary` (required, string): short, original summary (not full copyrighted article text).
- `firstPublishedAt` (required, string, RFC3339): original publication time.
- `lastPublishedAt` (required, string, RFC3339): last update time; used for sorting "Latest updates".
- `score` (required, number 0–100): HS-012 explainable score. Higher means more relevant.
- `evidenceLevel` (required, one of: `confirmed`, `unverified`, `unknown`): mirrors `domain.EvidenceLevel`.
- `publishers` (required, array): unique independent publishers deduplicated by `id`.

  - `id` (required, string): source identifier.
  - `name` (required, string): publisher display name.
  - `url` (required, string): direct link to the original coverage.

#### Latest articles (within `latest` array)

- `source_id` (required, string): source identifier.
- `source_name` (required, string): publisher display name.
- `title` (required, string): article headline.
- `url` (required, string): direct link to the article.
- `published_at` (required, string, RFC3339): article publication time.

#### Teams (within `teams` array)

- `slug` (required, string): team identifier used in URLs.
- `name` (required, string): full team name.
- `short_name` (required, string): abbreviated team name.
- `abbreviation` (required, string): two- or three-letter team abbreviation.

### Determinism and idempotency

The export produces deterministic output:

- Stories are sorted by `id` ascending.
- Publishers within each story are sorted by `id` ascending.
- Latest articles are sorted by `published_at` descending, then `source_id` descending.
- Teams are sorted by `slug` ascending.
- The `generatedAt` timestamp is the only wall-clock field; content comparison excludes it for idempotency.

The Go engine compares content (excluding `generatedAt`) with the existing file on disk and skips the write if unchanged.
This ensures the site build produces identical output when no relevant content has changed.

### No-secret and no-body guarantees

The export contract enforces:
- Summaries are bounded at 1024 characters to prevent full copyrighted article text from leaking.
- Secret patterns (`password`, `token`, `api_key`, etc.) are scanned in summaries and rejected.
- Only whitelisted fields are exported; database credentials and private metadata are never included.

### Implementation notes

- The Go engine produces `web/data/homepage.json` via `cmd/export/main.go` when a refresh run executes.
- This directory is the *only* contract between the engine and the rendering layer.
- `internal/domain/scoring.go.ClassifyEvidence` maps to `evidenceLevel` one-to-one.
- Score ordering (desc) is applied by the template; the JSON file itself can be unsorted.
- `version` enables forward-compatible schema evolution.

## Empty states (HS-056)

The site renders a clearly-labelled empty state for every data-less condition.
No placeholder files with fake timestamps are ever committed:

| Condition | Homepage (`/`) | Feed dashboard (`/status/feeds/`) |
|-----------|----------------|-----------------------------------|
| `homepage.json` **missing** | "Story data unavailable. Please check back soon." (no timestamp) | — |
| `homepage.json` with **zero stories** | "No stories published yet" + truthful `Data as of <generatedAt>` | — |
| `feeds.json` **missing** | — | "Dashboard Unavailable. Feed health data is not yet available." |

### `generatedAt` honesty

`generatedAt` is the real wall-clock time the engine built the artifact from
the database records. The engine never backdates it, and when the content is
unchanged the file (and its original `generatedAt`) is preserved rather than
rewritten with a new timestamp. See `internal/adapters/hugo/data.go`.

## Publish decision (refresh-news, HS-056; manifest in Turso, issue #247)

The `refresh-news` workflow makes an explicit publish decision after export.
Under issue #247 the "last deployed" state is no longer a committed
`web/data/deployed.json` file — it is the **deployed manifest stored in the
shared database (Turso)**. Before the gate the workflow reads it with
`publish manifest get` (into an untracked workspace path) and invokes the
publish gate with `--require-manifest` so a fresh checkout with **no stored
manifest DENIES (fail closed)** instead of deploying an empty site.

- exported snapshot has **≥ 1 story** → deploy the snapshot to Pages, then
  record the manifest in Turso with `publish manifest put` (no Git commit);
- **zero stories** but the stored manifest had ≥ 1 story → **deny**: the last
  successfully deployed (real) content is retained, and the zero-story file
  is not presented as current;
- **zero stories** and **no stored manifest** (never deployed) → **deny**
  (`--require-manifest`): the site is not deployed with an empty homepage;
- **identical content** to the stored manifest → **skip** the deploy (quiesce);
- a failed ingest / export / **manifest read** fails the build job, so the
  deploy job is skipped and the last-good Pages deployment is preserved
  unchanged.

The only remaining Git-mutation step in the workflow is the **retention-only
commit** (issue #120 / HS-065), which commits only `archive/retention` (never
`web/data`) so `retention apply` can delete rows after the package is
persisted. A hard "Verify no demo markers" step greps the built `web/public/`
for the sample data signatures (`example.com`, `seed-run-`, and the demo
story IDs) and blocks any Pages upload that would present the sample as real
news.

## Using the fixtures

- **CI** — `scripts/site-test.sh` (the Site workflow's hard gate) overlays
  `web/fixtures/` onto `web/data/` + `web/content/stories/` for the test
  builds only, backed up and restored around the run, so every assertion has
  deterministic sample input regardless of the production data state.
- **Local development** — `make site-seed` copies the fixtures into
  `web/data/` and `web/content/stories/` (untracked copies) so
  `make site-watch` shows representative content. Remove them afterwards with
  `rm web/data/homepage.json web/data/feeds.json web/content/stories/top-free-agents-2024.md ...`;
  since issue #247 the `web/data/*.json` and generated `web/content/stories/*.md`
  files are gitignored, so a local seed is never accidentally committed.
  Note: with seeded copies in place, `go test ./internal/adapters/hugo/`
  intentionally fails (the production marker gate) until you remove them.
